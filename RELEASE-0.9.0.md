# 0.9.0 — «Волна 1» аудита: ядро обещания починено

Главное: закрыты **все критические (P1) и высокие (P2) находки** полного технического
аудита репозитория (ревизия 5c311df / v0.8.0, 100 находок, аудит от 2026-10-16) —
12 позиций «Волны 1» дорожной карты, каждая по критерию завершения из раздела 10.1.
Впервые в проекте появились юнит-тесты: **31 тест**, шаг CI «Unit-тесты» перестал
быть вакуумным.

## 1. Почему это важно: ядро обещания подорвано было кодом

Слоган 0.8.0 — «движок „в приложении“ надёжен по построению» — опровергался кодом
четырьмя независимыми дефектами, бившими в одну гарантию звонка:

- **AL-1 (P1)**: перезагрузка в окне «00:05 → время звонка» молча теряла будильник —
  маркер дедупликации переживал ребут, слот `AlarmManager` нет; `BootReceiver`
  и страховка 06:00 «подтверждали» мёртвый слот. Типичный триггер — ночная OTA
  (02:00–05:00).
- **AL-2 (P2)**: фоновый `SyncWorker` трактовал «startActivity не бросил исключение»
  как «будильник поставлен» — BAL-блокировка Android 10+ писала ложный маркер,
  и ночная сверка больше не исправляла.
- **AL-3 (P2)**: после ночи с выключенным телефоном (обе ночные сверки пропущены)
  движок «в часах» не восстанавливался.
- **AL-4 (P2)**: пересечение тестового и реального звонков плодило второй
  `MediaPlayer` — первый становился неостанавливаемым.

## 2. Движок будильников (было → стало)

| Ситуация | 0.8.0 | 0.9.0 |
|---|---|---|
| Ребут в окне «00:05 → звонок» | маркер «уже стоит» → тишина до звонка | проба фактического слота (`FLAG_NO_CREATE`) перед ранним выходом; `BootReceiver` сбрасывает маркер и перепоставляет безусловно (`rearmFromBoot`) |
| Телефон выключен всю ночь (в часах) | тики пропущены, будильника на сегодня нет | `BootReceiver` → сверка для обоих движков, пока время подъёма не прошло |
| Фоновая сверка (SyncWorker) | `SET_ALARM` из фона → возможна BAL-блокировка → ложный маркер | `allowClockDelivery=false`: фон правит только APP-слот; CLOCK-постановку делает ночной тик (allowlist) или тумблер |
| Тестовый звонок × реальный | второй `MediaPlayer` неостанавливаем | guard повторного старта: прежний звук/вибрация глушатся до нового старта |
| Тумблер × ночной тик × смена цели | гонка без мьютекса → двойной `SET_ALARM` / снятие свежепоставленного | все входы `AlarmGateway` сериализованы мьютексом |
| Выключение тумблера | настройка писалась ДО снятия; работа умирала вместе с экраном | engine-работа в `appScope`; при OFF сначала `dismissAll`, потом запись настройки |
| Тумблер во время engine-работы (до 12 с) | можно щёлкать посреди постановки | блокируется с индикатором (`toggling`), повторный клик не теряется |

## 3. Данные

- **[FIX DATA-1] Пустой ответ больше не стирает кэш.** Сервер КГЭУ на
  несуществующий/устаревший idGroup (смена учебного года) отвечает `state:1 + rasp:[]`
  ШТАТНО. Guard «стало 0 при было >0» сохраняет кэш и не штампует свежесть
  (баннер «устарело» честно горит); серия из 3 пустых синков подряд присылает
  уведомление **«Проверьте группу»** (2 новые строки × 15 локалей).
- **[FIX DATA-2] Убран `fallbackToDestructiveMigration()`** — будущая версия БД без
  миграции падает громко при старте, а не молча вытирает исключения и свои занятия.
- **[FIX DATA-11] `exportSchema=true` + `room.schemaLocation`** — JSON схемы (v2)
  коммитится в `app/schemas/`, возможны миграционные тесты и честный diff.
- **[FIX DATA-3] Миграция правил-исключений 0.6.0** (одноразовая, атомарный флаг
  DataStore): безпрефиксные правила («материаловедение»), молча сузившиеся в 0.7.0
  до несуществующего названия, расширяются на все полные названия дисциплины из кэша
  («л. + пр. + лаб. материаловедение»). Правила с типом в названии не трогаются;
  при пустом кэше правило остаётся как есть.

## 4. UI/настройки

- **[FIX UI-1]** «Сменить группу» работает сколько угодно раз за сессию: каждый вход
  в мастер сбрасывает ход прошлого запуска (`completing` и пр.) и перечитывает офсет.
  Критерий аудита («дважды подряд — обе завершаются») выполняется.
- **[FIX UI-7]** сбой записи настроек не роняет мастер (try/catch, кнопка жива).
- **[FIX UI-2 + SET-2]** `rememberSaveable` для шага мастера и всего стейта диалогов
  (сейверы для `Set<DayOfWeek>` / `LocalDate?` / `LocalTime`): поворот не сбрасывает
  мастер, не закрывает диалоги и не стирает ввод.
- **[FIX UI-3]** `BackHandler` на экране звонка глушит звук и закрывает экран.
- **[FIX SET-1]** пункт **«Язык системы»** в пикере (первой строкой, пустой тег) —
  возврат к системному языку теперь возможен, заявление README соответствует коду.

## 6. Что изменилось для пользователя

Ничего настраивать не нужно: обновление ставится поверх старых версий (один ключ
подписи). При первом запуске 0.9.0 выполняются одноразовые миграции (правила
исключений 0.6.0 расширяются по кэшу). Логика «одна ночь вперёд» не менялась —
починены отказоустойчивость и честность данных вокруг неё.

## 7. Честные ограничения (остаются из аудита, «Волны 2–3»)

- `allowBackup=true` без `dataExtractionRules` (SEC-1) — отложено в «Волну 2»;
  пока не менять: перенос на новый телефон через Google-бэкап восстановит данные.
- P3-группа: сеть из ресиверов → WorkManager (AL-5), локализуемая метка «Авто: …»
  (SET-5), форматтеры-синглтоны (SET-4), single-flight синка (DATA-8) и др.
- P4-гигиена: R8/shrinkResources выключены (INFRA-4), toolchain не поднимался
  (INFRA-2), мёртвые ключи 0.6.0 (SET-8) и пр.
- Дымовые instrumented-тесты на эмуляторе (ребут-сценарий AL-1) — следующий шаг;
  юнит-контракт восстановления уже зафиксирован тестами доставки/планировщика.
