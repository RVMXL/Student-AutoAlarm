# 0.10.0 — «Волна 2» аудита + два бага обратной связи

Главное: (1) приложение **больше никогда само не открывает стоковые часы** —
удалён автоматический переход `SHOW_ALARMS`, который выпрыгивал в часы при отказе
оболочки принимать `DISMISS_ALARM` (ColorOS/Realme UI не принимают его никогда);
(2) в движке «В приложении» появилась карточка **«Мои будильники»** — поставленные
будильники теперь видны в приложении. Плюс закрыта **вся P3-часть аудита**
(36 находок «Волны 2», кластерами) и включён **R8**: APK уменьшился с 13,1 до
**2,56 МБ**.

## 1. Баг 1: «зачем оно открывает стоковые часы?»

`DISMISS_ALARM` — официальный канал снятия будильников в часах, но ColorOS/Realme UI
его **молча игнорируют**. Приложение трактовало это как «не смогло» и включало
автоматический фолбэк — открывало список будильников часов (`SHOW_ALARMS`), чтобы
пользователь снял метки «Авто:» вручную. На практике это выглядело как необъяснимое
«выпрыгивание» стоковых часов — в том числе посреди смены движка на «В приложении».

**0.10.0:** авто-переход удалён из всех путей (тумблер, смена движка, кнопка
«Отключить будильники», ночная сверка). Неуспех объясняется снекбаром/уведомлением,
а в часы пользователь попадает **только по своей явной кнопке** — «Список
будильников» на карточке «Мои будильники» (в движке «В часах») или в настройках.

## 2. Баг 2: «в режиме приложения не видно поставленные будильники»

Новая карточка **«Мои будильники»** на главном экране:

- крупное время звонка + локализованная дата («вторник, 20 октября»);
- метка будильника и движок («В приложении» / «В часах»);
- статус слота: «стоит — сработает по расписанию» / «не найден в системе —
  перепоставится автоматически» (проба `FLAG_NO_CREATE` — честное состояние после
  перезагрузки до `BootReceiver` перепоставит);
- кнопка «Снять будильники» (гасит оба движка) и явная кнопка списка часов
  (только в движке «В часах» — там могут быть остатки «Авто:», которых приложение
  не видит);
- перечитывается на каждом возврате экрана на передний план (`LifecycleResumeEffect`).

## 3. Движок будильников («Волна 2», было → стало)

| Ситуация | 0.9.0 | 0.10.0 |
|---|---|---|
| DISMISS не принят при переносе будильника (AL-9) | предупреждали в логе и ставили новый → прозвенели бы ОБА | новый `SET_ALARM` не отправляется; маркер чистится; уведомление «снимите старый вручную» |
| Уведомления запрещены (AL-10) | звонок 10 минут без способа выключить | `AlarmFireReceiver` поднимает `RingActivity` (BAL-исключение будильников) |
| Android 14+ не выдал FSI (AL-11) | звонок тихо деградировал | проверка `canUseFullScreenIntent()` + карточка-подсказка с кнопкой исправления |
| Напоминание в APP-движке (AL-12) | «не забудьте поставить будильник» — дезинформация | показывается только в «В часах» |
| `!setupComplete` на ночном тике (AL-14) | цепочка тиков умирала навсегда | перепланирование — ДО любых ранних выходов |
| Медленная сеть в окне 10 с (AL-5) | 9-с обновление + сверка не влезали | бюджет сети 7 с; сверка на кэше успевает |
| Постановка по плану (AL-16) | тройное чтение `planFor` + TOCTOU | план передаётся в постановку как есть |
| Время (AL-21) | статический `LocalDateTime.now()` | инжектируемый `AppClock` |
| Звук звонка (AL-18) | `prepare()` на главном потоке; тишина при null URI | фоновый поток; будильник → звонок → уведомление |
| «Пропущен» (AL-19) | затирал «не поставлен» (ID 1002) | собственный ID 1007 |

## 4. Данные и сеть

- **[DATA-4]** свежесть — от успеха `/api/Rasp`: сбой `GetRaspDates` больше не
  означает вечный full-sync и ложный баннер «устарело».
- **[DATA-8]** single-flight: ночной тик × periodic × ручное обновление — строго
  по одному (мьютекс).
- **[DATA-9/10]** сетевые сбои → `Result.retry()` с экспоненциальным backoff
  (до 3 попыток); отмена воркера больше не глотается.
- **[DATA-13]** времена пар — это стенка-время Казани (UTC+3): приводятся к зоне
  устройства (вне UTC+3 будильник больше не сдвигается; зонно-независимый тест).
- **[DATA-5]** кэш прежних целей чистится; автодополнение исключений — только
  предметы текущей цели.
- **[DATA-6]** DataStore под corruption handler — побитый файл настроек не крашит.
- **[DATA-17/16]** HTTP-кэш OkHttp 5 МБ; User-Agent = фактической версии.
- **[DATA-12/14]** периодика WorkManager — `UPDATE`; миграции `Application` — в
  `appScope`.

## 5. UI/локализация

- **[UI-4]** разрешение уведомлений — ровно один запрос за сессию.
- **[UI-8]** «Назад» в мастере ходит по шагам.
- **[UI-9]** мьютекс на исключения (двойной тап не создаёт дубль правила).
- **[UI-14/15]** busy-гейт на «следующую неделю»; первая загрузка — индикатор
  вместо ложного «нет пар».
- **[SET-3/4/UI-5]** даты уведомлений следуют языку приложения на холодном старте;
  форматтеры — функции с локалью на момент вызова (после смены языка не остаются
  старые месяцы/цифры).
- **[SET-5]** метка звонка APP-движка локализована (в часы — по-прежнему стабильная
  «Авто: …»).
- **[SET-8/9]** 8 мёртвых ключей удалены (×15 локалей), поле `AccentPalette.name`
  удалено; паритет **15 × 245 ключей** — скрипт + юнит-тест.

## 6. Безопасность и инфраструктура

- **[SEC-1]** `allowBackup=false` + `dataExtractionRules` + `fullBackupContent` —
  бэкапы Google отключены, SECURITY.md теперь соответствует коду.
- **[SEC-4]** лимит тела ответа API — 5 МБ (OOM-защита от враждебного сервера).
- **[SEC-5]** actions запинены по SHA (`checkout` v4.4.0, `setup-java` v4.9.1),
  wrapper — `distributionSha256Sum`, в релизе — гейт сверки versionCode/versionName
  APK с тегом.
- **[INFRA-1/2]** NOTICE-ссылка исправлена; Dependabot подключён (gradle +
  github-actions) — майорные прыжки toolchain осознанно отложены.
- **[INFRA-4/SEC-8]** R8 + shrinkResources: **APK 2,56 МБ** (цель аудита ≤ 6 МБ
  перекрыта), релизная конфигурация собрана до публикации.

## 7. Что изменилось для пользователя

Ничего настраивать не нужно — обновление ставится поверх любых предыдущих версий.
Стоковые часы больше не открываются сами; поставленный будильник виден на главном
экране. Логика «одна ночь вперёд» (тумблер → сегодня/завтра, ночная сверка 00:05 +
страховка 06:00) не менялась.

## 8. Честные ограничения (остаются из аудита, «Волна 3»)

- P4-гигиена: инжектируемый `Clock` в остальных ~20 местах, key в списках
  Compose, контраст-аудит палитр, link-refs CHANGELOG, политика prerelease→stable.
- Toolchain: AGP 8.7.3 / Kotlin 2.0.21 / BOM 2024.12.01 не поднимались —
  Dependabot подготовит кандидатов, подъём — отдельной волной.
- Дымовые instrumented-тесты на эмуляторе (ребут-сценарий AL-1).
- SET-3 не полностью: уведомления локализуются, но «Экран часов при постановке»
  (CLOCK-движок) остаётся системным UI часов.
